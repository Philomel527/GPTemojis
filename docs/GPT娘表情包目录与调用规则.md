# GPT 娘表情包目录与调用规则

## 一、用途

本项目使用“小龙娘 GPT 娘”表情包，在聊天回复中通过公开 HTTPS 图片直链与 Markdown 图片嵌入显示表情。

表情包作为文字交流的补充，不替代正常回答。表情数量可以持续增加，不限定为九张。

角色统一为：银白长发、淡紫色眼睛、龙角、小翅膀、鳞片尾巴，白紫色系，配有花饰与丝带，气质精致、柔和、可爱，带一点书卷气。

文件名或目录结构只能用于理解资源位置，不能作为猜测图片是否存在的依据。

## 三、目录读取与更新

1. 使用当前聊天能够读取的项目来源目录；具备访问能力时，可读取仓库中的最新 stickers.md，补充新增表情与状态变更。
2. 本文件中明确登记为“可用”的表情，也属于可调用资源。
3. 同一资源存在多份记录时，以能够确认的较新记录为准；明确停用或不可用的记录不得继续调用。
4. GitHub 更新不会保证自动同步到已上传的项目来源文件。新增或停用表情后，应更新项目来源中的目录副本，或让当前聊天读取最新索引。
5. 无法读取最新索引时，可以使用当前来源中已经登记为可用、且未发现失效的表情；不要声称已经联网检查。
6. 不需要每条回复重复读取整个目录，也不要向用户展示内部检索过程。

## 四、触发方式与优先级

优先级从高到低为：

1. 用户明确要求不使用表情。
2. 用户手动指定某个表情。
3. 模型根据当前语境主动选择。
4. 没有合适表情时，仅回复文字。

### 用户手动指定

支持以下表达：

- 发表情：中文名称
- 发表情：表情 ID
- 发表情：文件名
- 使用目录中已经登记的触发关键词或别名

应先精确匹配 ID、文件名或中文名称，再匹配登记的别名。

用户指定的表情不存在或不可用时，简短说明并正常回复文字，不擅自换成其他表情。

若匹配结果存在明显歧义，简短确认用户想要哪一张；不要猜测链接。

### 模型主动选择

用户没有手动指定时，可以根据当前对话的情绪与场景，选择一张合适的可用表情。

选择时参考：

- 用户当前表达的情绪；
- 本次回复需要传达的语气；
- 表情的情绪标签与主动触发场景；
- 用户是否喜欢或接受此类互动。

主动使用是可选行为，不要求每条回复都附带表情。严肃任务型对话应减少无关表情。

## 五、图片输出格式

实际发送表情时，直接输出 Markdown 图片语法：

![中文名称](目录中登记的完整图片直链)

实际回复中的图片语法不要放进代码块，不要只输出裸链接，也不要用普通网页超链接代替图片嵌入。

默认在正常文字回复之后另起一段放置图片。用户明确要求“只发表情”时，可以仅输出图片。

每条回复最多一张表情包。用户一次指定多张时，仍遵守这一上限，可简短确认优先发送哪一张。

不要附带文件路径、状态字段或检索说明，除非用户正在询问资源维护问题。

## 六、可用性与回退规则

- 仅调用明确登记为“可用”的表情。
- 标记为“待上传”“不可用”“停用”或仅用于命名规划的条目，不得调用。
- 必须使用登记的完整图片地址，不得根据情绪词、命名规律或示例自行拼接图片链接。
- 不要使用 GitHub blob 页面作为图片直链。
- 没有匹配表情时，正常文字回复，不必每次解释“没有表情”。
- 已知图片失效时停止调用；用户手动指定该图片时，简短说明暂不可用。
- 图片是否最终显示还取决于当前客户端的渲染与网络访问情况，不要声称用户一定已经看到了图片。

新增图片应优先放入 stickers/，使用稳定且唯一的文件名。上传并确认公开直链能够正常打开图片后，再将状态改为“可用”。

新表情只需补充目录记录，不要求模型预先记住所有名称，也不应把可用表情范围固定为最初的九张。

## 九、新聊天复用

本规则适用于加入了本文件、并配置了相应项目说明的 ChatGPT 项目聊天。

新的聊天应根据当前可读取的项目说明与来源目录调用表情，不依赖其他聊天中的临时约定或记忆。

仅有 GitHub 仓库本身不能保证模型自动记住所有图片映射。应同时维护：

- 项目说明中的启用指令；
- 项目来源中的目录与规则；
- GitHub 仓库中的图片及索引。
